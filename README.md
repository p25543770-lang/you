# Пульт оператора робота

Веб-интерфейс управления роботом для машины на Ubuntu. Робот поднимает свою
точку доступа Wi-Fi, телефон или ноутбук к ней подключается, и пульт открывается
в браузере. Доступ — только после авторизации с ролью **оператор**.

## Текущий объём (версия 0.1.0)

Сделано:

- вход оператора: логин + пароль, сессия в подписанной cookie; в средах, где
  cookie не сохраняются (iframe-превью), работает резервная подписанная
  URL-сессия `st` с отзывом при выходе;
- защита: хеш пароля PBKDF2-HMAC-SHA256, CSRF-токен, блокировка после серии
  неудачных попыток, безопасные заголовки (CSP, X-Frame-Options, nosniff);
- **после входа — веб-интерфейс робота RUS SLAM**: основной экран на `/`
  (схема шасси с 4 модулями, АКБ, тяга, маршрут, журнал событий; только просмотр) и инженерный
  пульт на `/console` (карта SLAM, сервис двигателей, телеметрия, E-STOP);
- интерфейс взят из [danilka-revin/rus_slam](https://github.com/danilka-revin/rus_slam)
  и лежит в репозитории (`slam_gui/`) — робот без интернета, тянуть неоткуда;
- источник данных выбирается сам: ROS 2 → UART-модули → симуляция;
- макет как в референсе: служебная страница `/panel` — слева узкая колонка,
  в ней только бренд сверху и карточка пользователя (аватар, имя, роль, кнопка
  выхода) внизу; до входа колонки нет — форма входа центрирована на весь экран;
- скрипт точки доступа Wi-Fi через NetworkManager (`scripts/setup_ap.sh`);
- systemd-юнит для автозапуска (`scripts/robot-control.service`);
- тесты: 64 проверки (`pytest`).

## Быстрый старт

### Ubuntu: скачать с GitHub и запустить одной командой

Нужен Python **3.9+** (на Ubuntu 22.04 и новее стоит по умолчанию; установщик
сам проверит версию и поставит `python3-venv`, если его нет).

```bash
git clone -b arena/01a0fcfa-you https://github.com/p25543770-lang/you.git robot-control
cd robot-control
./scripts/install_ubuntu.sh
```

Скрипт сам создаст `.venv`, поставит зависимости, сгенерирует `.env` с секретным
ключом, спросит логин и пароль оператора, откроет порт 8080 в `ufw` (если он
включён) и запустит сервер. После этого с телефона или ноутбука в той же сети
пульт открывается по адресу `http://<IP-машины>:8080/`.

> **Интернет не нужен.** Все пакеты (Flask, gunicorn, pip) лежат колёсами в
> `vendor/`. Если сети нет, установка идёт офлайн через
> `--no-index --find-links vendor`. Робот сам раздаёт Wi-Fi, поэтому у машины
> обычно нет интернета — это нормально, запуск всё равно работает.

### Если не открывается с другого устройства

- Адрес — строго **`http://IP:8080`**, а не `https://`: TLS не настроен, по
  https сервер не ответит. Если браузер сам подставляет https (Edge/Chrome
  «всегда HTTPS»), отключите это в настройках или выберите «продолжить по
  HTTP» на странице ошибки.
- Фаервол: `start.sh` сам открывает порт в `ufw`, если тот активен. Вручную:
  `sudo ufw allow 8080/tcp` (посмотреть правила: `sudo ufw status`).
- Сервер должен слушать `0.0.0.0`: в выводе `ss -ltn | grep 8080` слева должно
  быть `0.0.0.0:8080`, а не `127.0.0.1:8080`.
- Устройства должны быть в одной сети: с другого устройства должен проходить
  `ping <IP робота>`.

Полезные флаги: `--no-run` — установить без запуска; `--systemd` — поставить
автозапуск службой; `sudo ./scripts/setup_ap.sh` — раздать на роботе свою
Wi-Fi-сеть и подключаться к пульту через неё.

### Ярлык «Робот-пульт» (запуск в один клик)

```bash
./scripts/make_shortcut.sh   # ярлык в меню приложений и на рабочем столе
```

Ярлык запускает `scripts/start.sh`, который при **каждом** старте:
обновляет код с git (`reset` на `origin` текущей ветки), подтягивает
зависимости (pip ставит заново только при изменении `requirements.txt`,
при отсутствии pip в venv — ставит его сам), создаёт `.env`/учётку при
первом запуске, открывает порт в `ufw`, убивает старый сервер на порту
и поднимает новый **в этом же окне терминала**.

Закрытие окна или Ctrl+C останавливает сервер — висящих старых процессов
не остаётся. Остановка из другого терминала — `./scripts/stop.sh`.

Всё работает без вопросов: если спросить пароль негде (нет терминала),
учётка создаётся автоматически, а логин и пароль пишутся в
`data/credentials.txt` (права 600, в git не попадает).

### Хочу, чтобы всё запускалось само (при загрузке Ubuntu)

```bash
sudo ./scripts/install_ubuntu.sh --systemd
```

Ставит службу `robot-control`: старт при загрузке, автоперезапуск при падении,
учётка и `.env` создаются сами. Логи: `journalctl -u robot-control -f`.

Окно терминала не закрывается само: ярлык запускает `start_desktop.sh`,
который после остановки сервера ждёт нажатия Enter — видно и статус,
и текст ошибки, если что-то пошло не так.

### Вручную (для разработки)

```bash
sudo apt install python3-venv python3-pip
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env            # и вписать RC_SECRET_KEY
.venv/bin/python scripts/create_operator.py --username operator

.venv/bin/python run.py         # http://0.0.0.0:8080/  (production: gunicorn)
.venv/bin/python run.py --dev   # встроенный dev-сервер Flask, только отладка
```

Ключ сессии генерируется так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Без `RC_SECRET_KEY` приложение поднимется, но с временным ключом: после
перезапуска все сессии слетят.

## Интерфейс робота (RUS SLAM)

После входа открывается веб-интерфейс робота-курьера. Он взят из
[danilka-revin/rus_slam](https://github.com/danilka-revin/rus_slam) и лежит
в репозитории в `slam_gui/` (номер исходного коммита — в
`slam_gui/UPSTREAM_COMMIT.txt`), чтобы робот работал без интернета.

| Адрес | Что там |
| --- | --- |
| `/` или `/main.html` | **Основной экран** (только просмотр): слева меню в стиле инженерного пульта — разделы этого экрана, журнал событий, связь с бортом, оператор смены («Сервис» открывает пульт); справа шапка с маршрутом, режимом и часами, полоса тревог, АКБ и тяга, схема шасси с 4 модулями (угол руля, обороты, температура). Без связи с сервером показывает последние значения как устаревшие; демо-данные только с `?demo=1` |
| `/console` или `/index.html` | **Инженерный пульт**: карта SLAM, сервис двигателей, телеметрия, журнал доступа, E-STOP |
| `/panel` | Служебная страница пульта: кто вошёл, кнопка выхода |
| `/api/state`, `/api/health`, `/api/audit` | Данные для интерфейса (JSON) |
| `/api/lock/open`, `/api/lock/close`, `/api/lock/pin` | Ячейка хранения инженерного пульта: открыть по PIN, закрыть, сменить PIN (основной экран их не использует) |

**Вход:** `admin` / `1234` (по умолчанию). **PIN ячейки хранения (пульт):** `2580`
(заводской, меняется в интерфейсе или через `RC_SLAM_PIN`).

### Откуда берутся показания

Режим `auto` (по умолчанию) выбирает источник сам, по порядку:

1. **ROS 2** — если установлен `rclpy` (темы `/screen/state`, `/battery/voltage`,
   `/battery/current`, `/screen/motors`);
2. **UART-модули** — если установлен `pyserial` и найден живой порт
   (`/dev/ttyUSB0…3` или `/dev/ttyACM*`); кадры телеметрии 16 байт, 20 Гц;
3. **Симуляция** — если ничего не найдено: интерфейс полностью рабочий, но
   на модельных данных. Так можно проверять пульт на обычном ПК.

Какой источник сейчас используется, видно в чипе «сервер · …» в шапке основного экрана
и в `GET /api/health`. Закрепить режим: `RC_SLAM_SOURCE=sim|serial|ros`.

Замыкать реальные механизмы можно через переменные окружения
`RUS_SLAM_LOCK_CMD` / `RUS_SLAM_LOCK_CMD_CLOSE` (команда открытия/закрытия
замка) — без них ячейка отрабатывает вхолостую.

## Точка доступа Wi-Fi (робот сам раздаёт сеть)

Робот не подключён к интернету — он **сам является точкой доступа**. Телефон или
ноутбук подключается к его Wi-Fi и открывает пульт в браузере.

```bash
sudo ./scripts/setup_ap.sh --autostart            # поднять + поднимать при загрузке
sudo ./scripts/setup_ap.sh --status               # сеть, пароль, адрес
sudo ./scripts/setup_ap.sh --down                 # выключить
sudo RC_AP_SSID=ROBOT RC_AP_PSK='мой-пароль-8+' -E ./scripts/setup_ap.sh   # свои имя/пароль
sudo ./scripts/setup_ap.sh --iface wlp3s0         # конкретный адаптер
```

Или одной командой вместе с установкой:

```bash
sudo ./scripts/install_ubuntu.sh --ap --systemd
```

Скрипт создаёт в NetworkManager соединение `robot-ap` в режиме AP с адресом
`10.42.0.1/24` и раздачей DHCP (`ipv4.method shared`), включает captive portal
(телефон сам открывает страницу входа) и сохраняет пароль Wi-Fi в
`data/wifi.txt` (права `600`, в git не попадает). Пароль короче 8 символов
отклоняется; если `RC_AP_PSK` не задан и сохранённого нет — генерируется
случайный.

### Как подключиться

1. На телефоне/ноутбуке откройте список Wi-Fi и подключитесь к сети
   **`ROBOT-CONSOLE`** (пароль — в `data/wifi.txt` на роботе).
2. В браузере откройте **`http://10.42.0.1:8080/`** — именно `http://`, не `https://`.
3. Войдите под учёткой оператора (на роботе — в `data/credentials.txt`).

Нужен Wi-Fi-адаптер с поддержкой режима AP; при наличии `iw` скрипт это
проверяет и останавливается, если поддержки нет. Если адаптер был подключён к
другой сети, скрипт предупредит: интернет по этому Wi-Fi пропадёт (по кабелю —
останется).

## Учётки операторов

Пароль в открытом виде нигде не хранится — в `data/operators.json` лежит только
хеш, права на файл `600`, и в git он не попадает.

```bash
.venv/bin/python scripts/create_operator.py --username operator      # создать/сменить пароль
.venv/bin/python scripts/create_operator.py --list                   # список
.venv/bin/python scripts/create_operator.py --username operator --disable
```

Роль одна — `operator`. Других ролей хранилище не принимает. Имя учётки может
быть любым, в том числе `admin`; роль от имени не зависит.

**По умолчанию установщик создаёт учётку `admin` с паролем `1234`** — её же
использует автозапуск. Переопределить можно переменными окружения:

```bash
RC_OPERATOR=robot RC_OPERATOR_PASSWORD='свой-пароль' ./scripts/install_ubuntu.sh
RC_OPERATOR_PASSWORD=random ./scripts/create_default_operator.sh   # случайный пароль
```

Логин и пароль дублируются в `data/credentials.txt` (права `600`, в git не
попадает). Сменить пароль позже:

```bash
.venv/bin/python scripts/create_operator.py --username admin --min-length 4
```

Пароль `1234` короткий: для отладки годится, для точки доступа, которую видит
всё вокруг, — лучше длиннее.

## Симуляция ROS + ИИ (страница `/brain`)

Отдельная живая симуляция поведения робота: граф ROS-подобных узлов и
нейросетевой контроллер на **40 нейронах** (диапазон 32–48). Открывается после
входа на `/brain` (то же, что и весь пульт, — под авторизацией).

- **Граф узлов** (`robot_control/brain/bus.py`, `runtime.py`): `WorldNode`
  (физика и сенсоры), `MissionNode` (точки маршрута), `BrainNode` (ИИ),
  `ModulesNode` (модули руления). Топики: `/cmd_vel`, `/odom`, `/scan`,
  `/goal`, `/brain/activity`, `/modules/state`. Настоящего rclpy в проекте нет
  (ROS 2 ставится не через pip), поэтому шина повторяет его модель
  (издатели, подписчики, таймеры) на чистом Python. Страница показывает
  частоты топиков в Гц.
- **Физика** (`world.py`): склад 14×9 м, стеллажи, велосипедная модель с рулём
  (предел 30°, скорость руля 35°/с — как в `SimSource`), 16 лучей лидара по 4 м.
- **ИИ** (`network.py`): рекуррентная сеть с утечкой, вход 20 (лидар, курс и
  расстояние до цели, скорость), выход 2 (скорость и руль). Веса хранятся в
  `robot_control/brain/weights.json`, пересчёт нового числа нейронов — через
  `train.py`.
- **Обучение** (`train.py`, `episode.py`): эволюционная стратегия (μ, λ) на
  чистом Python, старт от рефлекторной инициализации (`reflex_prior`).
  Награда: за точку +100, за метр приближения к цели +10, за касание −20.

Переобучить (около 15–20 минут на 2 ядрах):

```bash
.venv/bin/python -m robot_control.brain.train --neurons 40 --gens 150 --pop 24
```

Честно о качестве: сеть проходит часть маршрута, но не всегда доходит до всех
точек. Итоговая проверка печатается при обучении и показывается на странице.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Проверяются: хеширование и сверка паролей, хранилище операторов, блокировка
подбора, вход/выход, доступ к панели только с ролью `operator`, требование
CSRF-токена, игнорирование внешнего `next`, заголовки безопасности, 404,
а также CLI создания учёток — ограничение длины пароля по умолчанию и через
`--min-length`, сверка двух вводов, отсутствие пароля в файле в открытом виде —
и макет: левая колонка с пользователем только внизу, появляется после входа,
а до входа страницы отображаются без колонки. Отдельно покрыта резервная
URL-сессия: доступ к панели и выход по токену `st` без cookie, отклонение
подделанного токена и отзыв токена при выходе. CSRF-токен stateless (подписан
секретом и не зависит от cookie), поэтому вход работает и во встроенном
предпросмотре.

Если браузер не хранит cookie (iframe с opaque-origin), приложение переключается
на резервную URL-сессию: подписанный токен `st` добавляется в ссылки и формы,
а при выходе токен отзывается. Cookie остаётся основным механизмом; `st` —
только запасной для сред без cookie. Если и cookie, и `st` недоступны,
показывается подсказка открыть пульт в новой вкладке.

## Настройки

Все параметры — переменные окружения или файл `.env` (см. `.env.example`):
`RC_SECRET_KEY`, `RC_OPERATORS_FILE`, `RC_BIND_HOST`, `RC_PORT`,
`RC_COOKIE_SECURE`, `RC_MAX_FAILED_ATTEMPTS`, `RC_LOCKOUT_SECONDS`,
`RC_SESSION_MINUTES`, `RC_PBKDF2_ITERATIONS`, `RC_OPERATOR`,
`RC_OPERATOR_PASSWORD`.

Интерфейс робота:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `RC_SLAM_SOURCE` | `auto` | `auto` \| `sim` \| `serial` \| `ros` — откуда брать показания |
| `RC_SLAM_PORTS` | автопоиск | UART-порты модулей через запятую (`/dev/ttyUSB0,…`) |
| `RC_SLAM_LOCK_FILE` | `data/lock.json` | файл PIN-кода и журнала ячейки хранения (пульт) |
| `RC_SLAM_PIN` | `2580` | заводской PIN ячейки хранения (пульт) |
| `RC_SLAM_MAX_ATTEMPTS` | `5` | попыток ввода PIN до блокировки |
| `RC_SLAM_LOCK_SEC` | `30` | на сколько секунд блокировать после серии ошибок |

При работе по HTTPS включите `RC_COOKIE_SECURE=true`, чтобы cookie сессии
помечалась как `Secure`.
