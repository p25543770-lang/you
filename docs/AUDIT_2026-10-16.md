# Аудит функций и безопасности: RUS SLAM / пульт курьера

Дата: 2026-10-16. Метод: проверка по исходному коду, тестам и прошивкам, а не по README.
Тесты (`pytest`) на этом коде не заменяют испытания на настоящем роботе.

Условные обозначения статусов:

- **[ГОТОВО]** — реализовано в коде и покрыто проверками; на железе может не проверяться.
- **[ЧАСТИЧНО]** — часть реализована, часть отсутствует или не подтверждена.
- **[ДЕМО]** — показывает имитацию или выдуманные данные; не реальное состояние робота.
- **[НЕ СДЕЛАНО]** — в коде нет.
- **[НЕ ПРОВЕРЕНО НА ЖЕЛЕЗЕ]** — требует испытания на настоящем оборудовании.

## 2. Что исправлено в этой сессии

1. **СТОП тяги на пульте был имитацией.** Кнопка меняла только состояние браузера, а журнал писал «UART ×4». Теперь:
   - `POST /api/stop` на 8080 (вход оператора + заголовок) пересылает PWM 0 на бортовой экран и возвращает реальный итог;
   - журнал пишет «СТОП тяги подтверждён» или «НЕ подтверждён: причина»;
   - кнопка переименована в «СТОП ТЯГИ», подсказка говорит, что это не аварийный выключатель.
2. **Консоль: имитация выдавала себя за отправку команд.** Убраны «homing command → UART ×4», «Nav2: цель доставки», «Пауза Nav2», «/cmd_vel-гейт». Подписи переведены в «симуляция».
3. **Демо-камеры помечены как LIVE.** Теперь «ДЕМО · не камера», жёлтый цвет.
4. **CSP `frame-ancestors` разрешал встраивание любым сайтом.** Убраны `https://*` и `http://*`.
5. **Замок кейса без внешней команды молча работал программно.** Теперь журнал пишет «ТОЛЬКО программно», а при ошибке команды — «состояние неизвестно».
6. **Устаревшие тексты:**
   - `/panel` показывал заглушку «Управление роботом ещё не подключено» — заменено на служебную страницу со ссылками;
   - докстринг `robot_control/__init__.py`;
   - `slam_gui/README.md` утверждал, что D18 не используется (прошивка его использует);
   - README: 465 → 529 тестов; API-таблица дополнена `/api/stop`;
   - комментарий со ссылкой на несуществующий `rus_slam_base`.

## 3. Решения, которые нужно подтвердить

1. **СТОП без PIN (изменено).** Раньше `POST /api/drive` и `/api/kiosk_drive` с `percent: 0` без PIN-сессии возвращали 401, и тест `test_operator_drive_requires_login_pin_and_drive_header` это фиксировал. Из-за этого СТОП с пульта 8080 не мог пройти: PIN-сессия живёт в браузере киоска. Сейчас **нулевая тяга не требует PIN**; ненулевая — требует, лимит 20 % не менялся, заголовок и вход оператора обязательны. Watchdog 650 мс и тормоз прошивки не ослаблены. Если нужно вернуть прежнее поведение — откатить `is_stop_request` в `slam.py`, но тогда кнопка на 8080 не сможет остановить шасси.
2. **Заводской PIN `7232`** в `slam_gui/backend.py` (`DEFAULT_PIN`) и в `.env.example` (`RC_SLAM_PIN`). Его нужно сменить при установке (`POST /api/lock/pin`). Автоматическую смену не делал: это изменило бы поведение установщика на уже развёрнутых роботах.
3. **HTTPS.** Без него PIN и пароль идут открытым текстом по Wi-Fi. Нужен отдельный этап (сертификат для точки доступа или обратный прокси).
4. **Киоск 8090 без авторизации на API.** `/api/kiosk_*` открыты в сети робота по дизайну; руление и тяга закрыты PIN-сессией, открытие замка — PIN с блокировкой. Доступ по Wi-Fi надо ограничить паролем точки доступа.

## 4. Не проверено на настоящем роботе

Тесты и симуляции не заменяют эти проверки:

- четыре Arduino Mega: I²C-шина, адреса 2/3/4, задержки, перезапуски плат;
- сборка прошивок `avr-gcc`/`arduino-cli` на целевой машине;
- рулевые шаговые моторы TB6600: полярность, калибровка по D18, ноль, ±32°, выравнивание 2,5°;
- BLDC-контроллеры: полярность, PWM на D3 (цифровой, не аналоговый 0–5 В), тяга ±20 %, тормоз;
- **тяга только с вывешенными колёсами**, с независимым аварийным выключателем в силовой цепи;
- реальный лидар: RPLIDAR, LD19, LDS-01/02, OpenCR; порт, скорость, протокол, автопоиск;
- JBD BMS: порт, банки, защиты, CSV;
- камеры: USB-вебки через OpenCV (нужна установка `opencv-python-headless`), MJPEG на 11.6″ экране;
- замок кейса: внешние команды `RUS_SLAM_LOCK_CMD`/`RUS_SLAM_LOCK_CMD_CLOSE` и реле;
- стоп по сети: нажать СТОП ТЯГИ на пульте при работающих моторах, проверить итог в журнале и физическую остановку;
- точка доступа Wi-Fi и captive-portal на целевом адаптере;
- установка на чистой Ubuntu, автозапуск, обновление из GitHub в сети робота.
