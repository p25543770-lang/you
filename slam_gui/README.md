# Пульт RUS SLAM

Веб-панель управления роботом-курьером 4WIS/4WID в визуальном языке [ZMK Vision](https://github.com/danilka-revin/zmk-videoanalytics): тёмный сайдбар `#101b17`, акцент `#d5ff45`, светлая рабочая зона `#f3f5f7`.

Сейчас крутится **симуляция** (одометрия, лидар, камера, модули, FSM, e-stop). Клавиши: WASD / стрелки, Q/E — крабовый сдвиг, пробел — стоп, H — хоминг.

Основной экран робота — `main.html` + `main.css` + `main.js`: слева меню в стиле пульта
(разделы этого экрана, журнал событий, связь с бортом, оператор смены; «Сервис» открывает
пульт), справа маршрут, заряд и напряжение АКБ, тягу, тревоги и крупные показатели модулей
шасси. Он только показывает состояние; демо-данные — только с адресом `?demo=1`.
Бортовой киоск (`robot.html`) открывает по свайпу вправо экран поворота модулей,
а по свайпу влево — отдельный экран камер и логов. Переключающих кнопок нет:
каждый экран открывается только своим направлением свайпа. После PIN можно задавать угол каждому рулевому
модулю по отдельности. Реальная команда доступна только в режиме `master`, при
связи/калибровке/остановленном модуле; отправляется только
целевой угол, тяговые моторы и PWM не затрагиваются.

Запуск в этом репозитории (окна открываются отдельно):

```bash
./scripts/serve.sh                         # операторский сервер на 8080
./run_kiosk.py --no-open                   # киоск на 8090 без запуска браузера
RC_SLAM_SOURCE=master RC_SLAM_PORT=/dev/ttyACM0 ./run_kiosk.py --no-open
sudo systemctl enable --now robot-control robot-kiosk  # автозапуск (по желанию)
./scripts/autostart.sh off                             # выключить автозапуск целиком
```

`RC_SLAM_SOURCE` задаёт `sim` (стенд), `serial` (UART-модули), `ros` (ROS 2) или
`master` (один UART мастера и адресный поворот рулевых модулей). В режиме
`master` после PIN разрешены только индивидуальные целевые углы рулевых шаговых
моторов. Автозапуск по умолчанию выключен: приложение запускается вручную
(`./scripts/start.sh`, `./scripts/kiosk.sh`). Документация установки:
`docs/DEPLOY_UBUNTU.md`.

Файлы инженерного пульта: `index.html`, `styles.css`, `vision.js` (карта/камеры/лидар), `app.js` (симулятор),
`console-core.js` (ядро сервисного пульта без DOM), `console.js` (вкладка «Сервис»:
замок ячейки по PIN, ручное управление двигателями, АКБ 12S3P, статистика).

Проверки этого репозитория:

```bash
.venv/bin/pytest -q
node --check slam_gui/robot.js
python3 -m compileall -q robot_control slam_gui tests
```

Откройте `index.html` или поднимите static-сервер из этой папки:
`python3 -m http.server 8080 --directory .`. Полное описание — `docs/GUI.md`,
план окна «Сервис» — `docs/SERVICE_CONSOLE.md`.

## Мастер-Arduino по одному UART (`RC_SLAM_SOURCE=master`)

- `firmware/motor_master/motor_master.ino` — мастер (FL). Принимает команды из порта, рассылает их узлам по I2C и опрашивает их.
- `firmware/motor_node/motor_node.ino` — узел (слейв). Адрес задаётся `MY_ADDRESS`: 2 = FR, 3 = RL, 4 = RR.

Мастер раз в 200 мс печатает в порт строку телеметрии на каждый модуль:

```
@TLM mod=FL deg=-9.25 tgt=0.00 moving=1 cal=1 cycle=0 calib=0 opto=0 t=12345
```

Строки других видов в мониторе сервер игнорирует. После PIN-инструкции пульт
отправляет `w FL 12.0` или `w RR -8.0`: мастер маршрутизирует команду только
указанному рулевому шаговому мотору. Текущая серверная проверка требует свежую
телеметрию, калибровку и остановленный модуль; прошивка повторно проверяет угол
(±32°), калибровку и занятость. Команда не содержит скорости/PWM и не включает тягу.

Запуск: `RC_SLAM_SOURCE=master RC_SLAM_PORT=/dev/ttyACM0 ./scripts/serve.sh`
(для отдельного киоска: `RC_SLAM_SOURCE=master RC_SLAM_PORT=/dev/ttyACM0 ./run_kiosk.py`).
Требуется `pip install pyserial`. Закройте Serial Monitor: порт может быть занят только одним процессом.
Шаги моторов формирует таймер (прерывание 20 кГц) на всех платах. Печать телеметрии и обмен по I2C не останавливают движение, поэтому моторы не расходятся на длинных движениях и в циклах.
Обороты и температура не измеряются, поэтому на экране они пустые. Модуль, который не отвечает, тоже пустой.
